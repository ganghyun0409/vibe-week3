# Page Check

정적 HTML 페이지를 5가지 관점에서 점검하고, 문제를 심각도별로 분류해서 한국어로 보고하는 스킬입니다. 이 5가지는 초보자가 가장 자주 놓치는 항목이면서 동시에 스크립트로 객관적으로 검증 가능한 항목이라 골랐습니다: title, 깨진 내부 링크, img alt, viewport 메타, UTF-8 인코딩.

## 사용 순서

1. **대상 파일 찾기**: 사용자가 파일을 지정했으면 그 파일을, 지정하지 않았으면 현재 디렉터리(또는 프로젝트 루트)의 `*.html` 파일을 찾아 사용합니다. 여러 개면 전부 점검 대상에 포함하세요.

2. **점검 스크립트 실행**: 판단을 스크립트에 맡기세요 — 정규식으로 눈대중 확인하지 말고 아래 스크립트를 실행해서 나온 JSON을 그대로 근거로 씁니다. 이 스크립트는 HTML을 실제로 파싱하고, 내부 링크는 파일 시스템에서 존재 여부까지 확인하며, 인코딩은 파일 바이트를 직접 디코딩해서 검증합니다.

   ```
   python <skill_dir>/scripts/check_page.py <file1.html> [file2.html ...]
   ```

   출력은 파일별 JSON 객체 배열이며, 각 파일마다 `checks.title`, `checks.broken_links`, `checks.img_alt`, `checks.viewport`, `checks.encoding` 다섯 개의 결과를 담고 있습니다. 각 결과는 `status`(`pass`/`warn`/`fail`)와, 문제가 있으면 `severity`(`critical`/`warning`/`suggestion`)를 포함합니다.

3. **JSON을 사람이 읽을 보고서로 변환**: 아래 "메시지 템플릿"을 참고해서 각 항목을 심각도별로 묶어 정리하세요. 템플릿에 없는 조합은 나오지 않으니, 스크립트가 준 `issue`/`status` 값을 그대로 매핑하면 됩니다.

## 메시지 템플릿

`{}`는 JSON 값으로 채우는 자리입니다. 줄 번호가 있으면 자연스럽게 문장에 녹여 넣으세요 (예: "12번째 줄").

**title**
- `fail` / `missing` → 🔴 [제목 없음] `<head>`에 `<title>` 태그가 없습니다. 브라우저 탭·검색 결과·스크린 리더에 페이지 제목이 표시되지 않습니다. → `<title>페이지 제목</title>`을 `<head>` 안에 추가하세요.
- `fail` / `empty` → 🔴 [제목 비어있음] `<title>` 태그는 있지만 내용이 비어 있습니다 ({line}번째 줄). → 페이지를 설명하는 제목을 채워주세요.
- `warn` / `too_short` → 🟢 [제목 개선] 제목이 "{value}"로 너무 짧거나 의미가 불분명합니다 ({line}번째 줄). → 페이지 내용을 잘 나타내는 제목으로 보완을 권장합니다.
- `pass` → 통과.

**broken_links** (`items` 배열의 각 원소마다 한 줄씩)
- 🔴 [깨진 링크] "{url}" ({line}번째 줄, `<{tag}>`) → 대상 파일을 찾을 수 없습니다. 경로가 올바른지 확인하세요.
- `items`가 비어 있으면 통과.

**img_alt**
- `missing` 배열의 각 원소 → 🟡 [alt 누락] `<img src="{src}">` ({line}번째 줄)에 alt 속성이 없습니다. 스크린 리더 사용자가 이미지 내용을 알 수 없습니다. → `alt="이미지 설명"`을 추가하세요 (순수 장식용이면 `alt=""`).
- `meaningless` 배열의 각 원소 → 🟢 [alt 텍스트 개선] `alt="{alt}"` ({line}번째 줄)가 파일명이나 의미 없는 단어입니다. → 이미지가 전달하는 내용을 구체적으로 설명해주세요.
- 둘 다 비어 있으면 통과.

**viewport**
- `fail` / `missing` → 🟡 [viewport 없음] `<meta name="viewport">` 태그가 없어 모바일에서 레이아웃이 깨지거나 글씨가 작게 보일 수 있습니다. → `<meta name="viewport" content="width=device-width, initial-scale=1">`을 `<head>`에 추가하세요.
- `warn` / `non_standard` → 🟢 [viewport 값 확인] `content="{content}"` ({line}번째 줄)가 표준 권장값(`width=device-width, initial-scale=1`)과 다릅니다. → 의도한 설정이 아니라면 표준값 사용을 권장합니다.
- `pass` → 통과.

**encoding**
- `fail` / `missing` (`has_korean: true`) → 🔴 [인코딩 선언 없음] `<meta charset="UTF-8">`이 없고 한글 텍스트가 포함되어 있어 글자가 깨져 보일 위험이 큽니다. → `<head>`의 첫 줄에 `<meta charset="UTF-8">`을 추가하세요.
- `fail` / `missing` (`has_korean: false`) → 🟡 [인코딩 선언 없음] `<meta charset="UTF-8">` 선언이 없습니다. → `<head>` 최상단에 추가를 권장합니다.
- `fail` / `wrong_charset` → 🔴 [잘못된 인코딩] `charset="{declared}"` ({line}번째 줄)로 선언되어 있습니다. → UTF-8로 변경하세요.
- `fail` / `declared_but_not_actual_utf8` → 🔴 [인코딩 불일치] UTF-8로 선언은 되어 있지만 실제 파일 바이트가 UTF-8이 아닙니다. → 에디터에서 파일을 UTF-8로 다시 저장하세요.
- `warn` / `position` → 🟢 [인코딩 선언 위치] charset 선언이 문서 앞부분(1024바이트 이내)에 있지 않습니다 ({line}번째 줄). → `<head>`의 첫 번째 태그로 옮기는 것을 권장합니다.
- `pass` → 통과.

## 보고서 형식

파일마다 아래 형식을 사용하세요. 항목이 없는 심각도는 "없음"이라고 적지 말고 통째로 생략해도 됩니다.

```
## 📋 페이지 점검 결과 — {파일명}

🔴 심각 ({개수})
- ...

🟡 주의 ({개수})
- ...

🟢 제안 ({개수})
- ...

✅ 통과: {통과한 항목 이름들을 쉼표로}
```

여러 파일을 점검했다면 파일별 보고서 뒤에 "총 N개 파일, 🔴 A개 / 🟡 B개 / 🟢 C개" 형태의 전체 요약을 한 줄 덧붙이세요.

## 주의할 점

- 이 스킬은 **점검(읽기 전용)** 이 기본 동작입니다. 파일을 자동으로 고치지 마세요. 보고서 마지막에 "원하시면 바로 수정해드릴까요?"처럼 한 번 물어보고, 사용자가 동의하면 그때 직접 수정하세요.
- 스크립트가 잡아내지 못하는 것도 있습니다 (예: `<a>` 앵커의 `#id`가 실제로 페이지 안에 존재하는지, alt 텍스트의 의미적 정확성). JSON 결과에 이상하게 느껴지는 부분이 있으면 스크립트를 맹신하지 말고 직접 파일을 열어 확인하세요.
- `python`이 없는 환경이면 스크립트 대신 파일을 직접 읽고 같은 5가지 기준으로 수동 점검하되, 판단 기준(제목 존재, 링크 파일 존재 여부, alt 속성 존재, viewport 메타, charset 선언)은 위 스크립트 로직과 동일하게 적용하세요.
